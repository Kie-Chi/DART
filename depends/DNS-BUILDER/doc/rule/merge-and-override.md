# Merge and Override Rules

This document explains DNSBuilder's "override" semantics during configuration merging, helping you predict the final result when using `include`, standard templates `ref/std:`, `mixins`, and other features.

## Merge Model Overview

- Basic behavior:
  - Dictionaries: recursive merge (same keys continue into the next level)
  - Lists: merged as "union of unique items" (uniqueness is determined by stringified results)
  - Dictionary/list mixed: attempts to "normalize both to dictionaries" before merging; if this fails, the child overrides the parent
  - Other types: child value overrides parent value
- Invariant: the result is generated by deep-copying the "parent"; source data is never modified

## Dictionary Recursive Merge

- Same-key dictionaries continue into the next level via `deep_merge`; keys that don't exist in the parent are directly copied from the child

Example:

```yaml
parent:
  service:
    command: ["named", "-g"]
    env:
      A: a
child:
  service:
    env:
      B: b
```

Result:

```yaml
service:
  command: ["named", "-g"]
  env:
    A: a
    B: b
```

## List Union Merge

- List merging uses a "stringified deduplication" union strategy:
  - First collect the stringified set of the parent list (`{str(item)}`)
  - Iterate through child items one by one; if the stringified result is not in the set, append it
- Note:
  - Two structurally different items whose stringified results are equal will be treated as duplicates and not appended
  - The order of merged items is "parent items first, new child items appended after"

Example:

```yaml
parent:
  util: ["vim", "dnsutils"]
child:
  util: ["dnsutils", "tcpdump"]
```

Result:

```yaml
util: ["vim", "dnsutils", "tcpdump"]
```

## Dictionary/List Mixed Merge

- When the parent is a dictionary and the child is a list, or vice versa:
  - First call `_normalize_to_dict` on each to normalize "list-form `KEY=VALUE`" into a dictionary
  - After successful normalization, perform a shallow merge on the two dictionaries (child overrides same keys)
  - If normalization of either side fails (raises `TypeError`), use "child overrides parent" directly

Example:

```yaml
parent:
  environment:
    HTTP_USER: root
child:
  environment:
    - "HTTP_PASS=root"
    - "VAR_ONLY"
```

Result (shallow merge after normalization):

```yaml
environment:
  HTTP_USER: root
  HTTP_PASS: root
  VAR_ONLY: null
```

## Scalar and Other Type Override

- Types that are neither dictionaries nor lists uniformly use the "child overrides parent" strategy
- For example: strings, numbers, booleans, null values, etc. directly replace the parent value

## Application Scenarios of Merging

- include preprocessing:
  - Processing configurations (especially merging of same-name configurations, primarily **images or services with the same name**)
- Service resolution and template mixing:
  - Merging parent templates (`ref:` or `std:`) with `mixins` through `deep_merge` with the child service; same keys in the child override parent/mixin keys

## Notes

- Unified usage:
  - When you need to "append" list items, ensure the string representation of each item is different to avoid being treated as a duplicate
  - For environment variables or `KEY=VALUE` lists, prefer the list format, which can be automatically normalized and merged
- Usage recommendations
  - For attributes that support multiple formats (e.g. `command: str | list`), consider carefully whether subsequent usage needs overriding or adding, and choose the appropriate format accordingly
    - If a subsequent service inheriting it needs to override the `command` behavior, use `str` directly
    - If different services inheriting it need to add different parameters, consider using `list`

## Example: include Merging and Override

```yaml
# a.yml
builds:
  bind:
    image: bind
    environment:
      - "HTTP_USER=root"

# b.yml
builds:
  bind:
    environment:
      - "HTTP_PASS=root"
    util: ["vim"]

# Main configuration
include:
  - a.yml
  - b.yml
builds:
  bind:
    util: ["dnsutils"]
    environment:
      HTTP_USER: admin  # Overrides same key
```

Merge result (key fragment):

```yaml
builds:
  bind:
    image: bind
    util: ["vim", "dnsutils"]
    environment:
      HTTP_USER: admin
      HTTP_PASS: root
```
